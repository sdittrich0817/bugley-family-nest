# Studio makers and books

- My Cast characters are `studio_creations` rows of kind `character`; their stored portrait is the reference image for later pictures. Why: reuse album save/delete/restore rules.
- Story Maker stores its map, immutable style/cast selection and ordered child-authored pages in a story creation’s details; server-only updates use optimistic version checks, and story coaching loads saved content through askBugley. Why: reuse family isolation, album lifecycle and audited AI/image paths without allowing browser edits to private storage.
- Comic Maker uses the shared StorySetup and BugleyStep flow, server-created age-band panels, hidden scene planning and saved one-time follow-ups; comicCells defines automatic page geometry including the wide big moment for screen and print. Image vision supplies speech placement, and dialogue/layer actions never generate or charge glow; askBugley reads comicId/panelId and the book Bible. Why: child authorship and simple screens with consistent art, private storage and text separate from images.
- Books are `studio_creations` of kind `book` whose details hold format, locked style/cast, Story Bible, ordered chapterIds, author/pen-name status, dedication and cover; chapters are ordinary story/comic creations with `bookId` and shared `project`. Bible updates come only from children's saved chapters via `absorbAndRecap`, and story/comic coaching reads the bible. Print-minimum rules live in `src/lib/book.ts`. Why: reuse maker lifecycles and album projects while one source keeps the whole book consistent.
- Arcade games (`games.ts` rules, `games.functions.ts`) serve only pre-made `game_content` rows edited in /admin; answers stay server-side, rounds are graded and rewarded (sparks, levels, game badges, capped bonus glow via giftGlowServer) only in server functions, and no AI runs during play. Why: kids can't cheat rewards and nothing unchecked is generated mid-game.
- PLAY launch games use parent-scoped `play_sessions` with bounded server-graded turns and optimistic move claims; finish_play_session locks child/session and atomically awards stars, badges and capped local-day glow. Shared stickers contain only checked object concepts and safe artwork through images.server; Bugdex stores private child-to-sticker keys. Doodle requests accept bounded strokes only, re-render server-side and safety-check before guessing. Why: no uploaded images, client scores, duplicate rewards or family text shared in the library.
- Game Builder games are `studio_creations` of kind `game` whose details are a validated game file (template + settings) read by fixed engines in `src/components/games/engines.tsx`; AI only fills settings from allow-listed values, art is library sprites or the child's own creations, and all game text is guarded on save. Why: kids design games without any generated code running.
- Printed books: kids only create `print_requests`; parents order through `print.functions.ts`, which re-quotes with Lulu server-side, records a `print_orders` row and charges via Stripe embedded checkout. The payments webhook marks it paid and `advanceOrder` (`print.server.ts`) builds PDFs (`print-pdf.server.ts`), runs Lulu validation and submits the job; Hub "Check status" re-runs it. Formats, markup and sandbox/live live in admin-edited tables. Why: no browser path can set prices or reach the printer, and each step is resumable.
- Every Studio image goes through `src/lib/images.server.ts` (guard, glow charge with refund, server-built prompt from admin style recipe + no-text suffix, admin-chosen Replicate model per mode, fail-closed AI image check, private `studio-images` storage). Character Lock: heroes store a reference set and fixed Character DNA (inserted verbatim into prompts); stories/comics/books lock style and snapshot the scene model on first use (`details.modelLock`, book-level for chapters); scenes with locked characters get a vision drift check with up to 2 free retries, logged to `drift_checks`. Max 3 locked characters per book. Why: one audited path and consistent characters even when admin defaults change.
- Studio creations are written only by server code; rename actions guard child text before an ownership-checked write, and only parent-mode sessions restore or purge within 30 days. The Studio never accepts uploads. Why: direct browser updates cannot bypass moderation or destroy work permanently.
- Character consistency and reference safety checks fail closed; immutable art snapshots include the model and style recipe, and portrait provenance is server-recorded. Why: outages, weak matches and changed defaults cannot silently deliver inconsistent art.
- Make a Picture uses server-enriched rendering instructions and a saved preview; upgrades atomically claim that owned preview, use its stored idea/style/hero and image reference, and replace the same album entry. Its distinct glow spend kind leaves other finished-image costs unchanged. Why: no client-controlled discount, duplicate upgrade or changed subject.
- Tell a Story uses StorySetup and BugleyStep with server-created age-band pages, saved follow-up markers, and hidden illustration planning from saved content; page edits preserve exact words and invalidate old art, and chapter conversion carries cover/model lock into the book. Why: one question per screen without losing authorship or Character Lock.
